# Skill Inventory 首版需求

Skill Inventory 为公司内部人员提供 Skill 管理和分发。首版在 Windows 本机运行并验收，包含管理网页、服务端 API、持久化存储，以及可后台运行的独立客户端。业务背景见 [原始需求](../promt.md)，术语见 [术语表](../GLOSSARY.md)。

## Skill 管理

- 每个 Skill 都是以 `SKILL.md` 为入口的文件包，可以包含脚本、参考资料和模板。仅含 `SKILL.md` 的包也有效。平台负责保存、校验和分发文件包，包内脚本由使用方按宿主机制处理。
- 名称与描述取自 SKILL.md 的 YAML frontmatter。名称最多 64 字符，由小写字母、数字及单个连字符分隔，全库唯一。首次发布前允许改名，发布后固定，归档继续保留名称。客户端通过名称识别 Skill。
- 管理员可以在线创建和编辑 `SKILL.md`，也可以通过 ZIP 导入或整体替换资源。导入后展示文件清单，发布前校验入口文件、元数据和包结构。
- 管理页支持按名称搜索、Markdown 预览、显式发布和查看发布历史。列表能区分未发布、已发布、有未发布修改和已归档。
- 新建或更新先保存为草稿。每次发布生成一个固定版本。管理员编辑下一版时，客户端仍可获取已发布版本。
- 删除从未发布的 Skill 时移除草稿。删除已发布的 Skill 时归档，管理端保留发布历史，客户端停止发现和下载该 Skill 的全部版本。

## 版本与读取接口

- 正式版本号用 `主.次.修订` 三段数字。发布时由管理员确认版本号，系统可预填下一修订号。同一 Skill 的发布版本号唯一，并绑定一份不可变的内容快照。
- 默认读取仍在分发且版本号最高的正式版。发布 `2.0.0` 后再发布 `1.5.1`，默认仍读取 `2.0.0`。指定版本号时精确匹配。
- 服务端提供标准 HTTP 接口，覆盖可用 Skill 列表、元数据、版本查询、`SKILL.md` 正文和完整文件包下载，并附可运行的请求示例。草稿内容仅在管理端可见。

## 账号与 RBAC

- RBAC 属于首版验收。内置管理员负责账号、角色、Skill 管理、发布及逐个 Skill 的角色授权。普通用户可以读取、下载获授权的 Skill。
- 管理员可以创建「研发」「测试」等角色。普通用户可拥有多个角色，可读范围是所拥有角色授权的并集。未授权给任何角色的 Skill 仅管理员可访问。
- 授权以整个 Skill 为单位，适用于列表、详情、版本查询、正文和整包下载。同一 Skill 的全部发布版本共用权限。授权变更保存后即用于后续请求。
- 网页和独立客户端使用同一平台账号登录。客户端将会话保存在 Windows 凭据管理器，服务与客户端重启后可继续使用。退出客户端会撤销当前会话，修改密码或停用账号会使原有会话失效。该客户端下的所有项目共用同一个账号的服务端权限。
- 桌面端可在登录时勾选记住账号和密码。登录成功后才保存，凭据写入 Windows 凭据管理器，且仅对同一服务端填充。便携演示默认填充示例客户端账密。

## Windows 客户端

- 提供命令行配置、立即同步和状态查询。客户端在当前 Windows 用户下手动启停，启动时同步一次，随后按可配置的间隔检查更新。
- 启用配置保存在本机。用户级和每个登记项目独立勾选每个 Skill，各自选择跟随最新版或固定版本。新演示的项目列表和勾选状态为空。
- 用户级根目录默认是 `~/.skills-inv`，可自定义。客户端支持登记和移除多个真实项目目录。同步将各范围勾选的项目写入对应根目录的 `.agents/skills/<名称>--<版本>/`。取消勾选或移除项目后，下次同步清理对应的受管副本，更换用户级目录时在安装成功后清理旧副本。
- 固定版本无法获取时，客户端报告该范围的错误，由用户决定是否修改版本。目标位置发生手动安装冲突时保留原文件。
- 服务端明确返回 Skill 已停止分发或账号已失去访问权限后，客户端在该次成功同步中停用对应的自管安装副本。服务端暂时不可达时保留上一次成功同步的版本。
- 便携演示以目标目录中的 `SKILL.md` 验收。Codex 专用入口可单独使用设备安装的 Codex。见 [Codex 集成决策](adr/0001-codex-skill-activation.md)。

## 技术与交付

- 前后端分离，采用 Spring Boot、Vue 和 SQLite。管理网页及 API 默认仅在本机开放。
- 在运行环境和依赖准备就绪的 Windows 上，提供一个入口同时启动前端和后端。交付说明覆盖依赖准备、启动方式、数据模型、接口请求示例、客户端配置和关键设计取舍。

## 验收场景

| 场景 | 预期结果 |
| --- | --- |
| Windows 启动与重启 | 一个入口启动前端和后端。重启后，账号、角色、授权、草稿和已发布版本仍可查询。 |
| 在线创建与 ZIP 导入 | 可创建纯正文 Skill，也可导入带资源的 Skill；管理端能预览正文和核对文件清单。 |
| 草稿与发布 | 首次发布前，消费接口无法读取草稿。发布 `1.5.1` 后继续编辑，消费接口仍提供原发布版。发布 `2.0.0` 后默认读取切换为 `2.0.0`，也可精确拉取 `1.5.1`。 |
| 最高版本 | 已有 `2.0.0` 时再发布 `1.5.2`，默认仍返回 `2.0.0`，指定 `1.5.2` 时返回该版本。 |
| 角色授权 | 两个普通账号获得不同角色，分别验证列表、详情和历史版本下载范围。有多个角色的账号可以读取授权并集。 |
| 客户端登录 | 首次用账号密码登录，重开客户端及重启服务后可继续同步。退出登录、修改密码或停用账号后原会话失效。 |
| 同步范围 | 检查真实用户级目录收到最新版，项目 A 单独收到固定旧版，项目 B 未勾选时无副本、勾选后收到最新版。 |
| 后台同步与断网 | 跟随最新版的项目获取新版本，固定版本的项目继续使用指定版本。服务端暂时不可达时，保持上次同步成功的版本。 |
| 撤权与归档 | 撤权或归档后，受影响账号无法读取各版本。客户端下一次收到服务端可用 Skill 列表时隐藏对应条目，同步清理各范围的受管副本。管理员仍可查看归档的发布历史。 |
| 固定版本与安装冲突 | 固定不存在的版本时显示错误。目标有手动安装的同名 Skill 时报告冲突，并保留原文件。 |
